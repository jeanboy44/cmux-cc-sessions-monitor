# cmux-cc-sessions-monitor 설계

## 의도와 이유

cmux에서 여러 Claude Code 세션을 동시에 돌리면 어떤 세션이 일하는 중인지, 내 입력을 기다리는지, 끝났는지 알려면 워크스페이스를 일일이 돌아다녀야 한다. 이 도구는 cmux 안의 터미널 패인에서 돌아가는 Rust TUI로, 모든 Claude 세션의 진행현황을 한 화면에서 타일 형태로 보여주고, 타일을 고르면 해당 워크스페이스와 패인으로 이동시킨다. 화면은 도트(픽셀) 감성으로 꾸미고 Claude Code 마스코트 풍의 도트 캐릭터가 세션 상태를 표정으로 보여준다. 저장소는 GitHub 공개 저장소로 public으로 공개한다.

## 목표

- cmux에서 실행 중인 Claude Code 세션 전체를 한 화면에서 훑어볼 수 있다.
- 세션마다 타일 하나. 타일에는 도트 마스코트, 세션 이름, 상태, 사용자가 고른 부가정보가 보인다.
- vim 방식 이동(`h` `j` `k` `l`)으로 타일 사이를 옮긴다. `Enter`를 누르면 확대하지 않고 해당 워크스페이스의 해당 패인(탭)으로 포커스만 옮긴다.
- 상태는 네 가지로 구분한다. 일하는 중(running), 입력 대기(needs input), 대기(idle), 완료(done).
- 부가정보는 사용자가 설정에서 골라서 켜고 끈다.
- 뷰는 두 가지를 모두 제공하고 설정에서 고른다. A는 가로형(마스코트 좌측, 작게 많이 담김), B는 세로형(마스코트 상단, 크게 보임). 세션 수에 따라 자동으로 고르는 옵션도 둔다(제 추측으로 추가).
- 세션 상태와 해당 세션이 작업 중인 브랜치의 PR 상태를 연결해서 보여준다.

## 비목표와 안티골

- 세션 안에 입력을 보내거나 Claude를 조종하는 기능은 만들지 않는다. 읽기와 포커스 이동만 한다.
- 타일을 선택해서 확대하는 방식은 만들지 않는다. 이동은 cmux의 포커스로 처리한다.
- cmux가 아닌 다른 멀티플렉서(tmux 등)는 지원하지 않는다.
- Claude 외의 에이전트(Codex 등)는 이번 범위가 아니다.
- 토큰이나 사내 URL, 개인 경로를 저장하거나 코드·문서에 넣지 않는다. 공개 저장소이기 때문이다.
- 실패 기준(기능이 돌아가도 실패로 보는 경우): 화면이 네트워크 조회 때문에 멈추거나, 로그인이 안 된 `gh`·`az`가 있다고 TUI가 죽거나, 입력 대기 상태를 놓쳐서 한눈에 보는 의미가 없어지는 경우.

## 확인된 사실 (cmux 0.65.1, Claude Code 2.1.x, 조사 결과)

- `~/.claude/sessions/<pid>.json`: 세션 하나에 파일 하나. 필드는 `pid`, `sessionId`, `cwd`, `name`, `version`, `startedAt`, `updatedAt`, `statusUpdatedAt`, `status`. `status` 값은 `busy`, `idle`, `shell`을 관찰했다. 죽은 프로세스의 파일이 남을 수 있으므로 `kill -0 pid`로 생존 확인이 필요하다.
- `~/.cmuxterm/claude-hook-sessions.json`: cmux hook이 기록하는 파일. 세션마다 `agentLifecycle`, `runtimeStatus`, `hookEventName`, `lastBody`, `surfaceId`, `workspaceId`, `pid`, `cwd`, `transcriptPath`, `updatedAt`이 있다. cmux 공식 문서상 라이프사이클은 `running`, `idle`, `needsInput`, `unknown`이며 실제 파일에서는 `backgroundWorkPending`도 관찰했다. 조사 시점에는 `needsInput`이 실제로 기록된 사례를 보지 못했다. 이 파일은 cmux 내부 형식이다.
- `cmux sessions list`: sessionId와 workspace/surface UUID, cwd, `pid_exists`를 돌려준다.
- `cmux tree`: window, workspace, pane, surface 구조와 tty를 돌려준다.
- `cmux list-status`: 워크스페이스별 `claude_code=Running|Waiting`(`work=running|waiting`) 태그. 입력 대기와 단순 대기를 구분하지 못한다.
- `cmux read-screen`: 화면 텍스트를 읽는다. `cmux focus-pane`, `workspace select`로 포커스를 옮긴다.
- cmux `sidebar-state`의 `git_branch`는 워크스페이스 셸의 위치 기준이라 Claude 세션의 실제 작업 위치와 다를 수 있다. 사용하지 않는다.
- 사용자 환경에서 대부분의 세션은 세션 cwd가 이미 git 워크트리다. 일부는 메인 저장소(`develop`) 루트에서 시작해 Bash 명령 안에서 워크트리로 `cd`하며 작업한다.
- `gh`와 `az`(azure-devops 확장)가 설치되어 있다. 조사 시점에 `gh` 키링 로그인은 만료 상태였다.

## 상태 판정 (제 판단)

우선순위 순으로 시도하고, 앞 단계가 실패하거나 없으면 다음 단계로 넘어간다.

1. `~/.claude/sessions/<pid>.json`의 `status`(스파이크 결과: `waiting`이 권한 승인 대기로 즉시 반영되므로 입력 대기, `busy`와 `shell`은 running, `idle`은 idle).
2. cmux hook 세션 파일의 `agentLifecycle`과 `hookEventName`(보조 신호: 입력 대기 기록이 약 6초 늦고 승인 후에도 낡은 값이 남을 수 있다).
3. 필요할 때만 `cmux read-screen` 화면 패턴으로 입력 대기를 확인한다(예: 권한 승인 프롬프트).

완료(done)는 세션이 종료되었거나 hook의 종료 신호가 있을 때로 하되, 정확한 판정 규칙은 빌더가 실제 관찰해서 정한다. 파일 형식은 느슨하게 파싱하고, 알 수 없는 필드나 값이 있어도 죽지 않으며 `unknown` 상태로 표시한다. README에 "cmux 0.65 기준"이라고 명시한다.

## PR 연결

세션과 PR은 브랜치로 연결한다.

1. 세션 프로세스의 cwd(`lsof`)를 `git worktree list`와 대조해 워크트리와 브랜치를 정한다. 기본 경로다.
2. 세션 cwd가 메인 저장소(`develop` 등)이면 보조 신호로 추정한다. 하위 프로세스의 cwd와 transcript 끝부분의 최근 도구 호출 경로가 어느 워크트리 아래인지를 가장 최근 것 기준으로 본다. 이렇게 얻은 매칭은 사용자가 정한 대로 "추정"으로 표시한다(타일에 `~`). 이 보조 신호는 설정에서 끌 수 있다.
3. 어디에도 매핑되지 않으면 PR 없음으로 표시한다.
4. 브랜치를 소스로 하는 열린 PR을 조회한다. remote 호스트를 보고 GitHub이면 `gh pr list --head`, Azure DevOps이면 `az repos pr list --source-branch`를 쓴다. 사용자의 주 환경은 Azure DevOps이므로 `az`를 먼저 구현하고 GitHub은 그다음이다.
5. 조회는 백그라운드 스레드에서 30~60초 간격으로 하고 결과를 캐시한다. 화면 그리기는 절대 조회를 기다리지 않는다. 이미 로그인된 `gh`와 `az` 세션을 그대로 쓰고 토큰은 저장하지 않는다.
6. 표시 항목은 PR 번호, 제목, 상태(draft, 리뷰 대기, 승인, 충돌), CI 결과다. 기능 자체는 기본 꺼짐이고 부가정보 선택에서 켠다.

에이전트 상태와 PR 상태를 합친 강조 표시(예: 대기인데 승인된 PR이면 "머지 가능")는 PR 정보를 켰을 때만 동작하는 선택 기능이다. 사용자가 이 강조까지 원하는지는 아직 답이 없었으므로 기본은 정보 표시만 하고, 합친 강조는 후속 단계로 둔다(제 판단).

## 화면

- 도트 감성. 픽셀풍 색상과 굵은 테두리, 마스코트 스프라이트를 터미널 문자로 구현한다(예: 하프블록 `▀▄█` 문자로 도트를 표현). 선택된 타일은 노란 테두리로 보인다.
- 마스코트는 사용자가 정한 대로 Claude Code 마스코트를 그대로 쓰지 않고, 거기서 영감만 받은 독자 도트 캐릭터를 새로 만든다(공식 도안과 구별되는 실루엣과 이름을 갖는다). 상태별 표정은 다르게 한다. 일하는 중은 활기찬 동작(예: 주황 몸에 파란 불꽃), 입력 대기는 노란 색에 느낌표 깜빡임, 대기는 눈 감고 졸기, 완료는 초록 색에 체크. 색과 소품은 대화 중 목업에서 쓴 참고안이고 최종 도안은 빌더가 정한다. 공식 마스코트의 도안을 복제하지 않으므로 별도의 저작권·상표 확인 게이트는 두지 않는다.
- 게임풍 디자인 방향(사용자 요청): 마스코트뿐 아니라 전체 UI를 게임 느낌으로 만든다. 상단 바는 게임 HUD(세션 수와 상태별 개수를 아이콘+숫자로), 타일은 캐릭터 카드, 선택 커서는 깜빡이는 `▶` 화살표와 두꺼운 테두리, 설정 창은 게임 메뉴 창으로 꾸민다. 부가정보 중 수치(경과시간 등)는 HP바 같은 게이지로 표현할 수 있다. 상태 변화는 연출한다(예: 입력 대기로 바뀌는 순간 짧은 흔들림과 깜빡임, 완료가 되는 순간 한 번 재생되는 "클리어" 연출 후 마지막 프레임 유지, 새 세션이 나타날 때 등장 연출). 터미널 한계상 색과 문자 도트로만 표현하고, 애니메이션은 저사양에서도 부담 없게 12fps 단위의 프레임으로 제한한다.
- 애니메이션 참고 자료(사용자 제공): `https://patch-gg.github.io/pixelfx/`(MIT 라이선스 픽셀 이펙트 라이브러리). 참고할 원칙은 시간만으로 프레임이 결정되는 순수 함수형 애니메이션(루프가 이음새 없이 반복됨), 포즈는 12fps 단위, 예비 동작(anticipation)과 짧은 정지(freeze)와 흔들림(shake)으로 충격 표현, 작은 팔레트(어두운 색에서 밝은 색까지의 색 단계)다. 코드를 가져다 쓰지 않고 방식만 참고한다(브라우저용 JS 라이브러리이며 우리는 Rust TUI).
- 뷰 A(가로형): 마스코트 좌측에 작게, 우측에 이름·요약·브랜치·경과시간·상태 태그. 3열 격자. 한 화면에 9개 이상.
- 뷰 B(세로형): 마스코트 상단에 크게, 아래에 같은 정보. 세션 6개 안팎에 적합.
- 상단 바에 세션 수와 상태별 개수를 표시한다. 하단에 키 도움말을 표시한다.
- 터미널 크기에 따라 열 수를 조절하고 스크롤을 지원한다.

## 조작

- `h` `j` `k` `l`(방향키도 허용)로 타일 이동, `Enter`로 해당 워크스페이스·패인에 포커스, `i`로 부가정보 선택 창, `q`로 종료. `Enter`는 `cmux focus-pane`과 워크스페이스 선택 명령으로 구현한다.

## 부가정보 (사용자가 선택)

설정에서 켜고 끌 수 있는 후보는 다음과 같다. 사용자가 구체적으로 고른 항목은 PR 상태뿐이었으므로 기본 켜짐은 제 판단으로 정한다. 기본 켜짐: 세션 이름, 상태, 작업 한 줄 요약, git 브랜치, 경과시간. 기본 꺼짐: 마지막 활동 시각, 최근 도구 호출, 컨텍스트·토큰 사용량, CPU·메모리, PR 상태.

## 설정

- 설정 파일은 `~/.config/cmux-cc-monitor/config.toml`(제 추측). 항목은 뷰 선택(`a`, `b`, `auto`), 부가정보 on/off, PR 조회 간격, 추정 매칭 on/off.
- 설정은 TUI 안의 설정 창(`i` 또는 별도 키)에서도 바꿀 수 있고 파일에도 저장된다.

## 기술 선택 (제 판단)

- Rust, `ratatui` + `crossterm`. 파일 감시는 `notify` 계열을 쓰되, 실패하면 폴링으로 대체한다. cmux와 `gh`·`az` 호출은 별도 모듈로 격리하고, 실패하거나 시간이 오래 걸려도 TUI가 멈추지 않게 한다.
- 이 저장소는 아직 git 저장소가 아니다. 공개 저장소 생성과 push는 사용자가 말하기 전까지 하지 않는다.

- 개인 경로·이메일·사내 정보 금지. 설정은 환경 독립적으로.

## 검토 후 확정한 내용 (모두 제 판단이며 사용자가 정한 것이 아님)

- 입력 대기 신호가 가장 큰 기술 위험이다. 첫 마일스톤을 관찰 스파이크로 둔다. 실제로 권한 승인 프롬프트를 띄워 hook 세션 파일, `~/.claude/sessions`, `read-screen`이 각각 어떻게 변하는지 기록하고, 그 결과로 판정 규칙을 확정한다. cmux 문서상 Claude Code hook은 cmux 래퍼(`claude` 실행)가 자동으로 주입하므로 별도 설치 단계는 두지 않는다. 다만 cmux 밖에서 시작한 세션은 hook이 없을 수 있다.
- `idle`은 세션이 살아 있고 프롬프트를 기다리는 상태, `done`은 세션 프로세스가 종료된 상태로 정의한다. 종료된 세션은 흐리게 표시해 기본 10분간 유지한 뒤 목록에서 제거한다. 유지 시간은 설정으로 바꾼다. 생존 확인(`kill -0`)은 "목록에 올릴지"가 아니라 "running/idle과 done을 가르는" 용도로 쓴다.
- cmux 밖에서 도는 Claude 세션은 목록에서 제외한다. 이동할 workspace/surface가 없기 때문이다.
- `Enter`는 대상 surface의 workspace를 선택하고 그 surface로 포커스를 옮긴다. 문서의 "패인(탭)"은 cmux 용어로 surface를 뜻한다. 모니터 TUI로 돌아오는 것은 사용자가 cmux에서 직접 전환하는 방식으로 두고, 포커스 이동 후 복귀 편의 기능은 v1 범위 밖이다.
- PR 조회는 remote `origin`만 본다. Azure DevOps의 organization, project, repo는 remote URL을 파싱해서 얻는다. 열린 PR만 조회한다. CI 결과 조회는 호출이 늘어나므로 v1에서 제외하고, v1의 PR 정보는 번호, 제목, 상태(draft, 리뷰 대기, 승인, 충돌)까지다.
- v1 범위: 뷰 A, B, auto와 설정 창, 상태 4종, PR 연결. 부가정보는 세션 이름, 상태, 한 줄 요약, git 브랜치, 경과시간, 마지막 활동 시각, PR 상태까지. 최근 도구 호출, 컨텍스트·토큰 사용량, CPU·메모리는 데이터 소스가 불분명하므로 v2로 미룬다. 위 "부가정보" 후보 목록에서 v2 항목은 v1 설정 창에 나타나지 않는다.
- 지원 환경은 macOS 전용이다. cmux가 macOS 앱이기 때문이다. 배포는 소스 빌드(`cargo install --git`)로 시작하고, 릴리스 바이너리와 brew는 이후 단계다.

## 빌더에게 맡기는 것

- 모듈 구조와 크레이트 선택의 세부, 마스코트 스프라이트의 정확한 픽셀 도안과 애니메이션 방식.
- `needsInput`과 `완료` 상태가 실제로 어떻게 기록되는지 관찰해 판정 규칙을 확정하는 일.
- 요약 한 줄을 만드는 방법(마지막 hook의 `lastBody`나 transcript 활용 중 선택).
- 터미널 크기에 따른 열 수 계산과 스크롤 동작.
