# 정령 카드 UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 세션 카드를 속성(불·물·얼음·전기)별 정령 한 마리로 교체하고, 상태·컨텍스트 사용률을 정령의 움직임·크기로 보여 주며, 완료 알림(안 읽음)은 cmux처럼 파란 테두리 깜빡임으로 보여 준다.

**Architecture:** `src/spirit/`가 정령을 칸 격자(점자 글자 + 24비트 색)로 그리는 순수 함수(`render`)를 제공한다. 카드(`ui::card`)는 장면 칸 격자를 그대로 버퍼에 쓴다. 상태는 기존 `Status`, 크기는 컨텍스트 사용률(`ctx_percent`)에서 온다. 안 읽은 알림은 `cmux list-notifications`에서 읽는다.

**Tech Stack:** Rust 2021 (rust-version 1.89), ratatui 0.30, crossterm 0.29, 새 크레이트 없음.

**Spec:** `docs/superpowers/specs/2026-11-04-spirit-ui-design.md` (+ 이 계획의 "완료 알림" 항목은 설계서에 후속으로 추가됨, 아래 Task 5).

## Global Constraints

- macOS 전용, Rust 2021, `rust-version = "1.89"`, 새 의존성 금지.
- 정령은 점자(U+2800) 몸체 + 24비트 색. 눈은 점자 점으로만 그린다: 칸 하나를 통째로 비운 어두운 구멍 + 흰 점(`⠂`) 하나(얼굴에서 흰색은 그것뿐), 깜빡이면 흰 점이 사라지고 구멍 가운데에 어두운 몸 색 점 두 개짜리 가로선(`⠤`)이 2프레임, 3~5초 간격 깜빡임. **몸 색으로 배경을 채운 칸 금지**(밝은 타일이 이어져 보임). 5개 상태 모두 같은 눈.
- 기본 크기 S = 11칸 × 5줄(몸 반지름 5.5 서브픽셀); 컨텍스트 사용률로 S/M/L 단계(M·L은 시안의 x2·x3 비율을 참고해 정하되 카드 폭 안에 들어가야 함).
- 속성: Fire, Water, Ice, Lightning(Melee 제거). 번개는 길고 짧은 뾰족한 가시가 번갈아 뻗고 길이가 깜빡인다.
- 애니메이션 약 15fps, 보이는 카드만 계산. 상태 표시: RUNNING=원소 입자를 오른쪽으로 쏨, NEEDS_INPUT=`?` 글자 칸이 오르내림 + 몸 맥동, IDLE=어둡고 느린 흔들림 + `z`, DONE=반짝임 + 통통, UNKNOWN=회색.
- 선택 카드 테두리는 `style::SELECTED`(cmux 파랑) 유지. 사용자 UI 문자열은 한국어. 개인정보 가드(`tests/no_personal_info.rs`) 통과: 홈 절대경로·실제 UUID·회사명 금지(테스트 경로는 `/home/user/...`). 커밋: `-c user.name=jeanboy44 -c user.email=noreply@users.noreply.github.com`, 끝에 `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. 소스 주석은 영어.
- 정령 시안(참조 구현, 커밋 5887834의 `examples/ghost_demo.rs`, `examples/eye_gallery.rs`)이 모양·팔레트·애니메이션의 기준이다. 모양을 임의로 바꾸지 말고 시안을 `src/spirit/`로 옮겨 구조화한다.

## Review Focus

1. 영역이 정령(11×5)보다 작거나 0×0일 때 패닉 없이 그려진다 (Task 2).
2. 컨텍스트 파일이 없음/깨진 JSON/오래됨/퍼센트가 100을 넘거나 음수일 때 크기가 안전한 단계로 떨어진다 (Task 3).
3. 거대한 세션 기록(수십 MB)에서 끝부분만 읽고, 마지막 줄이 잘린 JSON이어도 이전 `usage`를 찾는다 (Task 3).
4. 알림 목록 출력의 본문에 `|`·줄바꿈이 들어 있어도 파싱이 깨지지 않고, 세션이 없는 surface의 알림은 무시한다 (Task 5).
5. 안 읽음 깜빡임이 다른 세션 카드/선택 테두리와 구분되고, 읽음 처리되면 멈춘다 (Task 5).
6. 옛 설정(`theme = "melee"`)이 있는 파일은 크래시 없이 기본값 경로로 떨어진다 (Task 4).

### Task 2: 카드 통합과 애니메이션 구동

**사용자 결정(2026-11-04):** 카드 크기를 기존 Pochi 시절 세로형 카드(처음 `24×9`칸이었으나 사용자 결정: 폭이 넓어 보여 24에서 20으로 좁힘, `20×9`칸, 테두리 포함)에 억지로 맞춘다. 안쪽 18×7 = 정령 영역 + 글자 줄. 정령 S(11×5)는 이 안에 5줄이라 글자는 2줄만 남으므로, 정령의 카드용 최소 크기를 `11×4`(몸 반지름·눈 위치 재조정, 눈은 그대로 칸 하나 구멍 + 흰 점)로 줄여 4줄 + 글자 3줄(이름 / 상태 배지+경과 / 브랜치·PR 중 우선 하나)로 만든다. M/L 크기는 이 카드 안에서 중앙 정렬로 최대 `18×4` 영역 이내(L도 4줄을 넘지 않게 가로로만 키우거나 몸 반지름을 키우되 4줄 제한). 카드 크기는 크기 단계와 무관하게 20×9로 고정한다. 20×9에서 `card_cols`는 폭 100에서 5열이어야 한다.

**Files:** `src/ui/card.rs`, `src/ui/grid.rs`, `src/ui/screen.rs`, `src/app.rs`

**Interfaces:**

### Task 5: 완료 알림 깜빡임 (cmux 안 읽음 알림 → 파란 테두리)

**Files:** `src/source/cmux.rs`(`list_notifications`), `src/model.rs`(`Session.unread_notification: bool`), `src/merge.rs`/`src/refresh.rs`, `src/ui/card.rs`, `src/ui/style.rs`

**Interfaces:**
- Consumes: `cmux list-notifications` 출력 한 줄 형식 `index:id|workspaceId|surfaceId|read|unread|app|title|body|timestamp|workspace title`(실제 줄은 `0:<id>|<ws>|<surface>|read|Claude Code|<title>|<body>|<ts>|<ws title>`이고 읽음 열은 `read`/`unread`). 본문에 `|`나 줄바꿈이 들어 있을 수 있다 — 앞 5개 필드(`index:id|ws|surface|state|app`)와 뒤쪽 타임스탬프/워크스페이스 제목은 고정이므로 양 끝에서 파싱한다.
- Produces: `cmux::Notification { workspace_id, surface_id, unread: bool, title: String }`, `Cmux::notifications() -> Result<Vec<Notification>>`, `Session.unread_notification`(surface가 일치하는 `unread` 알림이 있으면 true), `style::NOTIFY_BLUE`(cmux 파랑)와 깜빡임 위상 함수 `style::blink_on(tick: u64) -> bool`(약 1Hz), 안 읽은 카드는 테두리를 파랑↔기본색으로 깜빡이고 선택 테두리와는 굵기/색으로 구분.

- [ ] **Step 1: 테스트.** 알림 줄 파싱(읽음/안읽음, 본문에 `|`가 있는 줄, 빈 목록, 잘못된 줄은 건너뜀), `merge`가 surface로 매칭하고 세션이 없는 surface는 무시, 안 읽은 카드의 테두리가 `blink_on` 위상에 따라 파랑/기본으로 바뀜, 읽음으로 바뀌면 깜빡임 멈춤, `unread_notification`이 Done/Idle/Running 어느 상태에서도 표시.
- [ ] **Step 2: 진단 단계(코드 변경 최소):** 사용자가 "cmux에서 완료 알림이 왔는데 화면은 갱신 안 됨"을 보고했다. `~/.claude/sessions/<pid>.json`의 `status`, 훅 파일(`~/.cmuxterm/claude-hook-sessions.json`)의 `agentLifecycle`, 알림의 시각을 현재 데이터에서 비교해 어긋나는 경우(예: 알림은 있는데 세션 상태는 아직 busy)를 찾는다. 원인이 우리 상태 판정 순서라면 `status.rs`의 규칙을 고치고 회귀 테스트를 추가한다. 원인을 못 찾으면 보고서에 관찰한 수치를 남긴다.
- [ ] **Step 3–5:** FAIL 확인, 구현, 전체 테스트, 하단 패인 실행해 보여 주기, 커밋 `feat: blink border on unread cmux notifications`.
